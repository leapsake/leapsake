# Leapsake — project map (start here)

Leapsake is a **privacy-first people-management app** (a personal CRM): people, pets, tags, a
relationship graph with derived kinship, milestones, and contact methods. It is
**offline-first** (local SQLite, no cloud dependency to use it) and built for **incremental,
shippable delivery**: every increment is usable on its own. It grows desktop → mobile → sync +
web → media, with a shared, client-agnostic data/core layer under all clients.

## The rule for every doc here

A doc here holds work that is still ahead, is **named for what it delivers**, and is **deleted
the day that work lands**. `plans/` gets _smaller_ over time: consolidate before you add. When
you finish one:

1. Move anything durable **next to the code it constrains**: a doc-comment, the package
   `README.md`, or an `ARCHITECTURE.md`. Not into another `plans/` file.
2. Delete the section, or the doc, and any pointer to it.
3. Let `git log` carry the history. No ✅, no "used to say", no dates, unless the date is a
   deadline or a clock still running.

A doc that is _deferred_ rather than _done_ keeps its detail, because the sequencing inside it is
the value ([`android-pipeline.md`](./android-pipeline.md), [`desktop-packaging.md`](./desktop-packaging.md)).
When [`shipping.md`](./shipping.md) is empty it goes too, and [`v0-2.md`](./v0-2.md) is promoted.
